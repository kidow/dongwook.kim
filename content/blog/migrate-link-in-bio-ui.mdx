## 마이그레이션 개요

링크 허브 성격의 페이지는 작은 레이아웃 변화가 체감 품질에 직접 연결됩니다.
이번 작업에서는 데이터 이전보다 UI 안정화를 먼저 끝내는 전략을 택했습니다.

## 왜 UI를 먼저 고정했는가

- 사용자가 가장 먼저 체감하는 것은 데이터 소스보다 시각적 일관성입니다.
- 라우팅과 카드 레이아웃을 먼저 맞추면 이후 데이터 마이그레이션 범위를 좁힐 수 있습니다.
- 커밋 단위를 작게 유지하면 회귀를 빠르게 되돌릴 수 있습니다.

## 운영 방식

먼저 정적 스켈레톤으로 레이아웃을 고정하고, 이후 데이터 연결은 컴포넌트 계약을 유지한 채 교체했습니다.
이 방식은 디자인과 데이터 변경이 한 PR 안에서 얽히는 문제를 줄여줍니다.
